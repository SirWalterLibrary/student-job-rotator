# 06 — UI behavior

Single page, plain HTML + ES modules, no build step. Files under `rotator/static/`:
```
index.html
css/theme.css      design tokens + base (07-theme)
css/layout.css     components and layout
js/app.js          boot, tab routing, refresh timers
js/api.js          fetch wrapper (adds X-Admin-Pin), error handling, PIN storage
js/dom.js          h(tag, attrs, ...children) helper, toast(), dialog helpers
js/dates.js        formatting: weekday/month names, Hijri (02), long/short date strings
js/today.js        Tab 1
js/calendar.js     Tab 2
js/manage.js       Teacher tools drawer
js/actions.js      absent/swap, shift-day, manual-change dialogs
```
Never compute "today" in the browser. Use `config.today` from `/api/config` and `/api/today`.

## Page frame
- Header (arch plate): Bismillah line (07), title **Khidmah Roster**, subtitle "Weekend class jobs".
- Top-right: **Teacher tools** button (gear/key). Opens the drawer. If a PIN is required and not unlocked, it opens the PIN dialog first.
- Two tabs (ARIA `role="tablist"`; left/right arrow keys move; Enter/Space activate):
  1. **Tab 1 label:** "Today" on Sat/Sun, "Next Weekend" on Mon–Fri (from `mode`).
  2. **Tab 2 label:** "Calendar".
- Selected tab stored in `location.hash` (`#today`, `#calendar`, `#calendar/2026-12`) so refresh keeps it.
- Footer: "Hijri dates are approximate." + small "Jazakum Allahu khayran".
- Data refresh: tab 1 reloads every 5 minutes and when the page becomes visible again. If `today` changed (midnight in
  Minnesota), reload everything.
- Loading state: skeleton rows. Error state: friendly message with a Retry button (never a blank page).

## Tab 1 — Today / Next Weekend
Data: `GET /api/today`. For each session in `sessions` render one **day card**:
- Title: `Saturday, November 7, 2026`; below it the Hijri date; badge: **Today** (is_today) or **Upcoming**.
- Table (real `<table>` with `<caption class="sr-only">`): columns **Job** | **Student**.
  - Job cell: icon + name; description in small text underneath if present.
  - Student cell: name (large). If `source` is `swap`: small chip with the note (e.g. "Covering for Aisha (absent)").
    If `manual`: chip "Set by teacher". If `student` is null: muted "No one available".
  - Projected rows (future days) look identical; no special label.
- Cancelled day: muted card, text "No class — the teacher is away." plus the note, and (if `next_held` is given)
  "Roles move to Sunday, November 8" using that session's date. Don't show the table.
- Empty roster (no jobs): card text "No jobs yet. Teacher tools → Jobs to add some."
- Teacher actions (visible only when unlocked, see below):
  - Per row: **Absent** button → swap dialog (actions.js).
  - Per card: **Teacher away — shift this day** button → confirm dialog → cancel_session.
  - Per cancelled card: **Bring back this day**.
  - Per row (menu): **Change student** → manual dialog; **Leave empty**.
- Weekday: two cards (Saturday, Sunday). Weekend: one card (today).
- On Saturday also show, below the card, a compact line "Tomorrow: <Sunday date>" with a link that jumps to the calendar for this month.

## Tab 2 — Calendar
Data: `GET /api/calendar?month=YYYY-MM`. One month at a time.
- Controls: **‹ Previous**, month label ("November 2026" + Hijri month range small), **Next ›**, **This month**.
  Disable prev/next when the API returns `null`.
- Grid: 7 columns **Monday → Sunday**, header row of weekday names. Columns Mon–Fri are narrow (just the day number,
  dimmed); Saturday and Sunday columns are wide (`grid-template-columns: repeat(5, 0.45fr) 2fr 2fr`) and contain the day
  number, Hijri day, and a compact list `Job — Student` (one line each, ellipsis if long).
- Cell states: today = gold ring; past = slightly dimmed; cancelled = diagonal-line pattern + "No class";
  swap rows get a small ⇄ mark with a tooltip/`title` of the note.
- Clicking (or Enter on) a Saturday/Sunday cell opens a **day dialog** with the same table as Tab 1 and the same teacher
  actions when unlocked.
- Narrow screens (< 700px): hide Mon–Fri columns; show each weekend as a stacked block "Weekend of Nov 7" with Saturday
  and Sunday cards one under the other.
- Print: `@media print` hides header buttons/tabs/drawer and prints the month grid in black on white.
- Months before `start_date` are not reachable (API returns prev=null).

## Teacher tools drawer (manage.js) — four accordion sections
Opens from the right (full width on phones). Focus is trapped; Esc closes; returns focus to the button.
1. **Students** — list (alphabetical), input + **Add student** button (Enter submits), per-student **Rename** and **Remove** (confirm).
2. **Jobs** — list in `sort_order` with ▲/▼ reorder buttons. **Add job** form: name, short description, icon (optional emoji).
   Each job is expandable: edit fields + a checkbox list of all active students labelled "Volunteers" (checking saves via
   `PUT /api/jobs/<id>/volunteers`). **Remove job** (confirm).
3. **Fairness & up next** — from `GET /api/queue`. For each job, an ordered list "Next in line": student name,
   turns so far, last served date. Highlight the first name. If `single_volunteer`: hint "Only one volunteer — they will do
   this job every time and can't be given other jobs." Help text: "Whoever waited longest goes next. Nobody repeats a
   job until everyone who volunteered has had a turn."
4. **Settings** — start date (date input limited to Sat/Sun check on save), **Export backup** (downloads JSON),
   **Import backup** (file input, confirm "This replaces everything").

Every change shows a toast ("Saved") and refreshes whatever is visible (tab content + queue panel).

## Unlock / PIN
- `api.js` holds the PIN in `sessionStorage` (`kr_pin`) after `POST /api/auth` succeeds. Sent as `X-Admin-Pin`.
- If config says `pin_required=false` → always unlocked.
- Locked state: teacher buttons are not rendered. A lock/unlock button in the header: "Teacher login" ↔ "Lock".
- A 401 from any call clears the stored PIN, re-locks the UI and opens the PIN dialog.

## Dialogs
- **Absent / swap**: title "{Name} is absent". Explains: "{Name} will take {Job} on the next class day; someone else
  covers today."
  Dropdown "Who covers today?": first option "Let the system choose (recommended)" (empty value → no `partner_id` is
  sent), then the job's volunteers from `GET /api/jobs`, excluding the absent student and anyone who already holds a role
  in today's card. Buttons: **Swap**, **Leave job empty today** (sends `vacant:true`), **Cancel**.
  After success, toast: "{B} covers today. {A} takes it on {next_date long form}."
- **Shift day**: "Teacher away on Saturday, November 7? No jobs will be assigned that day, and everyone's turn moves to
  the next class day." Optional note input. Buttons **Shift day**, **Cancel**.
- **Change student**: dropdown of the job's volunteers not busy that day.
- All dialogs use `<dialog>`, are keyboard accessible, and show server error messages (`error` field) inline.

## Accessibility and quality bar
- Contrast WCAG AA, visible focus ring, tap targets ≥ 44px, `lang="en"`; Arabic text spans use `lang="ar" dir="rtl"`.
- Color is never the only signal (badges have words).
- No layout shift on load; works at 360px width; works without JS errors in the console.
